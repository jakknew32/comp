# โปรแกรมสร้างสมุดระบายสี A4

เว็บแอปที่รับ **ภาพลายเส้น** แล้วจัดการทุกอย่างให้จนได้ **PDF ขนาด A4**
พร้อมหน้าปก กรอบมุมมน ชื่อกำกับ และเลขหน้า — พิมพ์ออกมาแล้วระบายสีด้วยหมวกได้ทันที

---

## ข้อจำกัดสำคัญที่ต้องรู้ก่อนใช้

**โปรแกรมนี้ใช้กับภาพลายเส้นเท่านั้น ไม่ใช่ภาพถ่ายจริง**

ถ้าใส่ภาพถ่ายจริง (เช่น รูปสัตว์ตัวจริง) ระบบจะได้เส้นตามรูปต้นฉบับ
ไม่ใช่ภาพการ์ตูนน่ารัก เพราะการเปลี่ยนภาพถ่ายให้เป็นการ์ตูนต้องใช้ AI
ซึ่งเวอร์ชันนี้ไม่มี หน้าเว็บจะเตือนให้ทราบทันทีถ้าตรวจพบว่าเป็นภาพถ่าย

สิ่งที่โปรแกรมทำให้ได้กับภาพลายเส้น:

- ลบเงาและไล่แสง ถ้าถ่ายจากกระดาษหรือสแกน
- ตัดกรอบเดิมที่ติดมากับภาพออก ไม่ให้กรอบซ้อนกัน
- ลบจุดรบกวนและรอยหยักจากการบีบอัด
- ทำเส้นให้หนาสม่ำเสมอเท่ากันทั้งหน้า
- ขยายเต็มหน้า A4 โดยไม่ยืดสัดส่วนภาพ

---

## วิธีใช้

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

เปิด <http://127.0.0.1:8000> แล้วลากภาพมาวาง กด **พิมพ์สมุดระบายสี** เพื่อเปิดหน้าต่างพิมพ์ของเบราว์เซอร์ (เลือกเครื่องพิมพ์ได้เลย ไม่ต้องบันทึกไฟล์ก่อน)

ไม่ต้องใช้ GPU และไม่ต้องต่ออินเทอร์เน็ตหลังติดตั้งเสร็จ

---

## ค่าที่ปรับได้

ทุกช่องมีค่าเริ่มต้นเป็น **อัตโนมัติ** ซึ่งโปรแกรมจะตัดสินใจเองจากภาพ
ไม่ต้องแตะก็ได้ผลลัพธ์ที่ใช้ได้ ถ้าไม่พอใจค่อยจูนเอง

| ค่า | ผลต่อผลลัพธ์ |
|---|---|
| ความหนาเส้น | ต่ำกว่าเส้นในต้นฉบับ = ย่อเส้นให้บางลง, สูงกว่า = หนาขึ้น, ต่ำกว่า 0 = อัตโนมัติ |
| ความไวต่อจุดรบกวน | เก็บจุดเล็ก ๆ ที่เป็นส่วนหนึ่งของงาน หรือล้างทิ้ง |
| จำนวนภาพต่อหน้า | 1 / 2 / 4 / 6 / 9 / 12 |
| กรอบมุมมน | เปิดหรือปิดกรอบรอบหน้า |
| มีหน้าปก / ชื่อกำกับ / เลขหน้า | เลือกส่วนที่ต้องการ |

ปุ่ม **ดูตัวอย่างหน้า A4** จะแสดงผลของภาพที่เลือกอยู่ทันที
เหมาะกับการลาก slider เพื่อหาค่าที่ชอบก่อนสร้างทั้งเล่ม

### การย่อเส้น

ตั้งความหนาเส้นให้**ต่ำกว่า**ความหนาที่มีอยู่ในต้นฉบับได้ โปรแกรมจะกัดเส้นให้บางลง
โดยวัดความหนาจริงของภาพ แล้วปรับจนตรงกับค่าที่ตั้งภายใน 1 พิกเซล

ข้อจำกัดที่ต้องทราบ: การย่อทำให้เส้นที่บางกว่าเป้าหมายหายไปทั้งเส้น
ถ้าย่อแล้วรายละเอียดหายมากเกินไป โปรแกรมจะ**คืนความหนาเดิม** และแจ้งเตือนบนหน้าเว็บ
ไม่ทำงานพังไปเงียบ ๆ

ชื่อกำกับใต้ภาพดึงจากชื่อไฟล์โดยอัตโนมัติ แก้ได้ทีละใบในหน้าเว็บ

---

## รายละเอียดผลลัพธ์

- ขนาด A4 จริง 210 × 297 มม. ที่ 300 DPI (2480 × 3508 พิกเซล)
- ภาพบีบอัดด้วย CCITT Group 4 แบบไม่สูญเสียรายละเอียด
  ไฟล์จึงเล็กมาก (สมุด 10 หน้า ประมาณ 100–200 KB) และเส้นยังคมชัดเมื่อพิมพ์
- ข้อความทั้งหมดเป็นภาพ ไม่ฝังเป็นข้อความ จึงไม่มีปัญหาการจัดวางสระภาษาไทย
  ข้อความจะออกมาถูกต้องทุกเครื่องที่เปิด PDF

---

## ข้อควรรู้

- **ความละเอียดภาพ** ควรยาวอย่างน้อย 1500 พิกเซล ถ้าต่ำกว่านั้นเส้นจะไม่คมเมื่อขยาย
- **สี** ภาพต้องเป็นเส้นดำบนพื้นขาว ถ้าภาพถูกระบายสีทับแล้ว
  โปรแกรมจะถือว่าเป็นก้อนทึบหนึ่งก้อน และจะไม่ตัดทิ้ง (กันงานหาย)
- **หน้าปก** แสดงภาพย่อสูงสุด 9 ภาพจากเล่มจริง และเลือกรูปร่างตารางให้เต็มที่สุดโดยอัตโนมัติ
- ไฟล์ภาพที่อัปโหลดถูกประมวลผลในหน่วยความจำเท่านั้น ไม่ถูกบันทึกลงดิสก์
- ไฟล์ที่อ่านไม่ได้จะถูกข้ามไปโดยไม่ทำให้ทั้งเล่มล้ม และจะแจ้งว่าไฟล์ใดถูกข้าม

---

## เส้นออกมา "ขาดๆ" แก้ยังไง

OpenCV ทำได้แค่กรองภาพ ไม่สามารถวาดสิ่งที่ไม่มีอยู่เดิมได้
ถ้าภาพออกมาไม่ครบ ให้ดูตามลำดับนี้

1. **ถ้าเป็นภาพถ่ายจริง** ต้องใช้ AI (ดูหัวข้อถัดไป) OpenCV ทำได้แค่ดึงเส้นขอบ
2. **เส้นเดิมหายระหว่างทำงาน** เพิ่มความละเอียดภาพต้นฉบับเป็น 1500 พิกเซลขึ้นไป
   ภาพเล็กเกินไปเส้นบางจะถูกเฉลี่ยหายเมื่อย่อภาพ
3. **รายละเอียดเล็ก ๆ หายไป** ลด "ความไวต่อจุดรบกวน" ลง โปรแกรมจะเก็บจุดเล็กไว้มากขึ้น
4. **เส้นหนาจนระบายสีไม่สะดวก** ลด "ความหนาเส้น" ลง โปรแกรมจะย่อเส้นให้บางลง
5. **ภาพถูกระบายสีทับแล้ว** โปรแกรมจะถือเป็นก้อนทึบหนึ่งก้อนและไม่ตัดทิ้ง
   เพราะกันงานหาย ต้องใช้ภาพที่ยังไม่ถูกระบายสี

## การใช้ AI ช่วยแปลงภาพถ่าย (ไม่บังคับ)

โปรแกรมทำงานครบโดยไม่ต้องมี AI
แต่ถ้าต้องการให้**ภาพถ่ายจริง** ออกมาเป็นภาพการ์ตูนน่ารักแบบตัวอย่าง
ต้องใช้ AI ซึ่งเป็นขั้นตอนเสริมที่ต้องเปิดใช้เอง

### ข้อจำกัดสำคัญ

**Render ไม่มี GPU** (ยืนยันจากเอกสารของ Render เอง ณ ปัจจุบัน
มีได้สูงสุด 32 GB RAM / 8 vCPU) จึง**รันโมเดลภาพเองไม่ได้**
ต้องเรียกใช้ API ภายนอกเสมอ ซึ่งแปลว่า:

- เสียค่าใช้จ่ายต่อหนึ่งภาพ (ประมาณ 0.039–0.067 USD สำหรับโมเดลภาพของ Google)
  100 ภาพ ≈ 4–7 USD
- ภาพจะถูกส่งออกนอกเครื่องผู้ใช้ ไปยังผู้ให้บริการ AI
- ต้องมีคีย์ของผู้ให้บริการ
- ถ้าเรียกไม่สำเร็จ โปรแกรมจะกลับไปใช้การประมวลผลปกติทันที ไม่ทำให้ทั้งเล่มล้ม

### ตั้งค่า

ใส่ตัวแปรแวดล้อมนี้ใน Render (แท็บ Environment)

| ตัวแปร | ค่า | หมายเหตุ |
|---|---|---|
| `AI_API_KEY` | คีย์ของคุณ | บังคับต้องมี ถ้าไม่มีฟีเจอร์นี้จะไม่แสดงบนหน้าเว็บ |
| `AI_MODEL` | `gemini-3.1-flash-image-preview` | เปลี่ยนได้ถ้าอยากใช้โมเดลอื่น |
| `AI_BASE_URL` | `https://generativelanguage.googleapis.com/v1beta` | เปลี่ยนได้ถ้าใช้ผู้ให้บริการอื่น |
| `AI_TIMEOUT_SECONDS` | `90` | เวลารอสูงสุดต่อภาพ |

ตรวจสถานะได้ที่ `GET /api/health` จะคืน `ai.configured: true/false`

### ข้อควรรู้

- เรียกใช้เฉพาะกับ**ภาพถ่าย** เท่านั้น ภาพลายเส้นจะไม่ถูกส่งให้ AI
  เพราะผ่านการประมวลผลปกติได้ดีอยู่แล้ว การยิง AI เป็นการเสียเงินเปล่า
- **โค้ดส่วนนี้ยังไม่ได้ทดสอบกับ API จริง** เพราะไม่มีคีย์ในสภาพแวดล้อมการพัฒนา
  เทสต์ครอบคลุมรูปแบบคำขอ การถอดคำตอบ และการล้มเหลวทุกทาง แต่ยังต้องลองจริงครั้งแรก
- ถ้าโมเดลที่เลือกถูกปิดให้บริการ ให้เปลี่ยนค่า `AI_MODEL` ตามรายชื่อโมเดลที่ใช้ได้ปัจจุบัน

## โครงสร้างโปรเจกต์

```
app/
  main.py            เส้นทาง API
  config.py          ค่าคงที่ A4 และพารามิเตอร์ทั้งหมด
  ai/                ขั้นตอนเสริมที่ใช้ AI (ไม่บังคับ)
    settings.py      อ่านค่าจากตัวแปรแวดล้อม
    gemini.py        เรียก API โมเดลภาพของ Google
  lineart/
    imgio.py         โหลดภาพ (รองรับชื่อไฟล์ไทย) และจัดการชื่อ
    detect.py        ตรวจว่าเป็นภาพลายเส้นหรือภาพถ่าย
    measure.py       วัดและปรับความหนาเส้น ทั้งหนาขึ้นและบางลง
    convert.py       pipeline หลัก
    text.py          วาดข้อความไทยเป็นภาพ
    compose.py       ประกอบหน้า A4
  book/
    layout.py        แบ่งภาพลงหน้า
    cover.py         หน้าปก
    pdf.py           รวมเป็น PDF
static/              หน้าเว็บ (HTML/CSS/JS ล้วน ไม่ต้อง build)
fonts/               Sarabun (SIL Open Font License)
```

## เส้นทาง API

| Method | Path | หน้าที่ |
|---|---|---|
| GET | `/api/health` | สถานะระบบและความพร้อมของฟอนต์ |
| POST | `/api/preview` | คืนภาพหน้า A4 หนึ่งหน้า (สำหรับดูตัวอย่าง) |
| POST | `/api/book` | คืน PDF ทั้งเล่ม |
| POST | `/api/validate` | คืนค่าที่โปรแกรมตัดสินใจเอง |

ค่าที่ส่งเป็น `null` จะถูกตีความว่า "ให้โปรแกรมตัดสินใจเอง"

## การเพิ่มรูป

เลือกทางใดทางหนึ่งก็ได้ รายการภาพจะเรียงตามลำดับที่เพิ่มเข้ามา

- **ลากวาง** — ลากไฟล์มาวางในกรอบหน้าเว็บ
- **เลือกไฟล์** — กดปุ่มเลือกไฟล์
- **วางจากคลิปบอร์ด** — กด <kbd>Ctrl</kbd> + <kbd>V</kbd> ที่ใดก็ได้บนหน้าเว็บ
  ใช้ได้ทั้งกับภาพที่คัดลอกจากเว็บ ภาพจากโปรแกรมวาดรูป และภาพหน้าจอที่ถ่ายด้วยเครื่องมือ screenshot
  รูปที่วางจะได้ชื่อกำกับเป็นลำดับอัตโนมัติ แก้ได้ตามต้องการ

ถ้ากำลังพิมพ์อยู่ในช่องชื่อกำกับแล้วกด <kbd>Ctrl</kbd> + <kbd>V</kbd>
โปรแกรมจะยังเพิ่มรูปให้ แต่จะไม่ขัดจังหวะการวางข้อความของช่องนั้น

## การ deploy บน Render

### ทำไมต้องใช้ Docker

**โปรแกรมนี้ต้องมี `libraqm` จึงจะวาดข้อความไทยได้ถูกต้อง**

wheel ของ Pillow มีโค้ดเรียก libraqm อยู่แล้ว แต่ไม่ได้ bundle ไลบรารีมาด้วย
ต้องติดตั้งจากระบบ (`apt`) ซึ่งทำได้เฉพาะตอน build image เท่านั้น

ถ้าไม่มี librqam โปรแกรม**ยังรันได้แต่ข้อความไทยจะซ้อนกันผิดตำแหน่ง**
โดยไม่มี error ให้เห็น จึงต้องตรวจเสมอ โปรแกรมมีการตรวจให้ 2 จุด:
log ระดับ error ตอนเริ่มเซิร์ฟเวอร์ และแถบแจ้งเตือนบนหน้าเว็บ
(`GET /api/health` จะคืน `fonts_ready: false`)

### วิธีตั้งค่า

1. push โค้ดขึ้น GitHub (ไฟล์ `Dockerfile` และ `render.yaml` อยู่ที่ราก repo แล้ว)
2. ใน Render เลือก **New + → Blueprint** แล้วชี้ไปที่ repo
3. Render จะอ่าน `render.yaml` แล้วตั้งค่าให้เอง
4. เมื่อ deploy เสร็จ เปิด log ดูว่าขึ้นว่า `ตรวจสอบฟอนต์ผ่าน` ถ้าไม่ผ่าน
   แปลว่า image สร้างไม่ได้ libraqm ต้องตรวจ `Dockerfile`

### ทดสอบในเครื่องด้วย Docker

```bash
docker build -t coloring-book .
docker run -p 8080:8080 coloring-book
```

### ข้อควรรู้เรื่องแผนฟรี

- หยุดทำงานเมื่อไม่มีคนใช้งาน และปลุกขึ้นช้าประมาณ 30 วินาที
- หน่วยความจำ 512 MB การประมวลผลภาพหน้า A4 ใช้ความจำไม่น้อย
  ถ้าพบว่าถูกหยุดบ่อยหรือช้า แนะนำให้เปลี่ยนเป็นแผน paid
- ตั้งจำกัดขนาดไฟล์ไว้ที่ 25 MB ต่อรูป เพื่อไม่ให้หน่วยความจำล้น
