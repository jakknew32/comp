# โปรแกรมสร้างสมุดระบายสี A4 — เว็บแอป (FastAPI + OpenCV)

## เป้าหมาย

ผู้ใช้ลากภาพลายเส้น (line art) เข้าเว็บ → โปรแกรมจัดการเองทั้งหมด → ได้ PDF ขนาด A4
หลายหน้า พร้อมหน้าปก กรอบมุมมน ชื่อกำกับ และเลขหน้า พิมพ์ออกมาเป็นสมุดระบายสีได้ทันที

## ขอบเขตที่ตกลงแล้ว (จากการสัมภาษณ์)

| หัวข้อ | การตัดสินใจ |
|---|---|
| รูปแบบผลลัพธ์ | **PDF สำหรับพิมพ์** — A4, เส้นดำบนพื้นขาว, พิมพ์แล้วระบายด้วยหมวกได้ทันที (ไม่ทำเวอร์ชันระบายสีบนจอ) |
| รูปแบบโปรแกรม | เว็บแอปในเบราว์เซอร์ |
| สถาปัตยกรรม | Python เบื้องหลัง (FastAPI + OpenCV ตัวจริง) |
| ประเภทภาพนำเข้า | **เฉพาะภาพลายเส้น** — ภาพถ่ายจริงอยู่นอกขอบเขตรอบนี้ |
| AI | **ไม่ใช้ AI** ทั้งหมด — OpenCV ล้วน |
| ระดับการควบคุม | อัตโนมัติเป็นค่าเริ่มต้น + ปรับค่าเองได้ผ่าน slider |
| เนื้อหาใน PDF | หน้าปก, ชื่อกำกับ + เลขหน้า, กรอบมุมมน, รองรับหลายภาพต่อหน้า |
| สารบัญ | ไม่ทำ (ตกลงกัน) |

### ขอบเขตที่ตัดออก — และผลกระทบที่ต้องยอมรับ

ภาพอ้างอิงแบบ kawaii line art **สร้างด้วย AI เท่านั้น** ความน่ารักของการ์ตูน (ตากลมโต สัดส่วนก้อน
หน้าอิ๋ว) เกิดจากการ "วาดใหม่" ไม่ใช่การกรองภาพ OpenCV ทำได้แค่:

1. เส้นหนาสม่ำเสมอ พื้นหลังขาวสะอาด — **ได้**
2. กรอบมุมมน + ป้ายกำกับล่าง + หน้าปก — **ได้**
3. สไตล์การ์ตูนน่ารัก — **ไม่ได้**

ดังนั้นผลลัพธ์จะเป็น "สมุดระบายสีที่วาดจากรูปต้นฉบับ" ไม่ใช่การ์ตูนน่ารักสไตล์ Canva
ต้องแจ้งผู้ใช้ทราบอย่างชัดเจนที่หน้าเว็บ ไม่ใช่ปล่อยให้เพิ่งเห็นผลแล้วผิดหวัง

### จุดต่อ AI ในอนาคต (ยังไม่ implement)

โครงสร้างออกแบบเผื่อไว้แล้ว: `lineart/convert.py` จะเป็นจุดที่ภายหลังแทรกขั้นตอน
`img2img` (FLUX.1-Kontext / SDXL + ControlNet lineart) ได้ โดยเพิ่ม provider ใหม่ต่อท้าย pipeline
เดิม ไม่ต้องแก้โครงสร้างไฟล์

## ค่าคงที่หน้ากระดาษ

A4 = 210 × 297 mm ที่ 300 DPI

- ขนาดพิกเซล **2480 × 3508 px**
- ขอบกระดาษ (margin) 12 mm
- กรอบมุมมน: รัศมี 8 mm, ความหนาเส้น 2.5 mm
- ความหนาเส้นการ์ตูนเป้าหมาย: 2.5 mm (≈ 29.5 px ที่ 300 DPI) — slider 1.0–5.0 mm
- ช่องว่างระหว่างช่องใน grid: 6 mm

**ทำ PDF แบบ raster ทั้งหน้า** (PNG 1-bit) แล้วห่อเป็น PDF
เหตุผล: คุมมุมมน/grid/ข้อความไทยได้เป๊ะทั้งหน้า และภาพลายเส้นแทบขาวล้วน
บีบอัด 1-bit ได้เล็กมาก — เหลือทางเลือกเป็น vector ในอนาคตถ้าต้องการความคมชัดขึ้น

## Pipeline แปลงภาพลายเส้น (`lineart/convert.py`)

ทุกขั้นมีพารามิเตอร์ที่คำนวณอัตโนมัติ แล้ว override ได้จาก slider

1. **โหลดภาพ** — `imgio.py`: ห้ามใช้ `cv2.imread` ตรงๆ เพราะพังกับชื่อไฟล์ภาษาไทย
   ใช้ `cv2.imdecode(np.fromfile(path, np.uint8), ...)` และ `PIL.ImageOps.exif_transpose`
2. **ตรวจประเภทภาพ** — `detect.py`: คำนวณสัดส่วนพิกเซลที่ "เกือบขาว/เกือบดำ" (เช่น <8% หรือ >92%)
   รวมจำนวนสีที่พบมาก, และค่า saturation เฉลี่ย
   - เกณฑ์เป็น line art (binary ratio > 0.90 และสีเฉลี่ยต่ำ) → ข้ามขั้นแปลง เข้า cleanup
   - ไม่ผ่านเกณฑ์ → ยังประมวลผลต่อแต่ติดป้ายเตือน `is_photo=True` ให้หน้าเว็บแสดง
3. **ปรับแสงสม่ำเสมอ** — `norm = gray / (GaussianBlur(gray, (0,0), sigma=25) + 1e-3)`
   ขั้นนี้สำคัญที่สุดสำหรับภาพที่ถ่ายจากหน้ากระดาษ (ลบเงา/ไล่แสง) ให้เหลือแต่เส้น
4. **ย่อขนาด** — ด้านยาวสูงสุด 1400 px (เร็วขึ้นมาก และความละเอียดที่ได้ไม่เกิน 300 DPI อยู่แล้ว)
5. **ดึงเส้น** — **XDoG** (Extended Difference of Gaussians): `sigma`, `tau≈0.98`, `phi≈18`
   ให้เส้นต่อเนื่องและสะอาดกว่า Canny มากสำหรับงานลายเส้น
   ทางเลือกสำรอง: Canny ที่คำนวณ threshold จาก median
6. **กำจัดจุดรบกวน** — `connectedComponentsWithStats` ตัด component ที่พื้นที่เล็กกว่า
   `min_area = 0.0002 × (H×W)` — **ต้องรักษาก้อนใหญ่ไว้** เช่นตาสีดำของการ์ตูน (ดูความเสี่ยงข้อ 3)
7. **ซ่อมเส้นขาด** — morphological close เคอร์เนลวงรี 3×3, 1–2 รอบ
8. **ปิดช่องว่าง** — `findContours(RETR_EXTERNAL)` + `drawContours(filled)` เพื่อให้เส้นที่ควรปิดวง
   เชื่อมกันจริง แต่ **ต้องเปิดกรณีพิเศษถ้าผลลัพธ์ทำให้ก้อนทึบ (ตา/ปาก) หาย**
9. **หนาเส้นให้สม่ำเสมอ** — `measure.py` วัดความหนาเส้นเฉลี่ยด้วย `distanceTransform`
   แล้ว dilate ด้วยเคอร์เนลวงรีที่ขนาด `(target_px - measured_px)` เพื่อให้ได้ความหนาเป้าหมายจริง
   นี่คือหัวใจของ "จัดการมาเอง" — ไม่ต้องเดาค่าตายตัว
10. **ครอปช่องว่าง** — `boundingRect` ของหมึก + ขอบเว้น 3% + รักษาสัดส่วนเดิม
11. **ขยายขึ้น A4** — resize เข้ากรอบเนื้อหาด้วย `INTER_LANCZOS4`

## การประกอบหน้า (`lineart/compose.py`, `book/`)

**โหมดภาพต่อหน้า:** 1 (เต็มหน้า, ค่าเริ่มต้น), 2 (1×2 แนวตั้ง), 4 (2×2), 6 (2×3), 9 (3×3), 12 (3×4)

ต่อช่อง:
- เส้นกรอบมุมมนรอบเซลล์ (radius 8 mm, หนา 2.5 mm)
- ภาพย่อขยายแบบ `contain` ให้พอดีช่องเสมอ ไม่ยืดสัดส่วน
- ชื่อกำกับ: ค่าเริ่มต้นคือชื่อไฟล์ (ตัดส่วนนามสกุล) ผู้ใช้แก้ได้ในหน้าเว็บ
  วาดใต้ภาพ กึ่งกลาง, ฟอนต์ Noto Sans Thai 20 pt
- เลขหน้า: มุมขวาล่างในกรอบ, รูปแบบ `หน้า N`

**หน้าปก (`book/cover.py`):**
- ชื่อสมุด (ผู้ใช้กรอก, ค่าเริ่มต้น "สมุดระบายสีของฉัน") ขนาดใหญ่กึ่งกลางด้านบน
- ตารางย่อภาพ 6 ภาพแรก (2×3) อยู่ในกรอบมุมมน
- บรรทัดรอง: "ชื่อเล่ม · จำนวน N หน้า · วันที่สร้าง"
- หน้าปก **ไม่** มีเลขหน้า

## API (`app/main.py`)

| Method | Path | รับ | คืน |
|---|---|---|---|
| GET | `/api/health` | — | สถานะ + เวอร์ชัน |
| POST | `/api/preview` | 1 ไฟล์ + params | PNG หน้าเดียว (เร็ว, ใช้ตอนลาก slider) |
| POST | `/api/book` | หลายไฟล์ + params + layout | PDF ทั้งเล่ม |
| POST | `/api/validate` | params | ค่าที่ server คำนวณจริง (คืนกลับมาแสดงใน UI) |

`params` รับค่าที่คำนวณอัตโนมัติได้ด้วยการส่ง `null` — เช่น `{"target_line_mm": null}` เท่ากับให้เซิร์ฟเวอร์ตัดสินใจเอง

**อัปโหลด:** `multipart/form-data`, จำกัดขนาดต่อไฟล์ 25 MB, รองรับ JPEG/PNG/WEBP,
ชื่อไฟล์ไทย/มีช่องว่าง (decode ด้วย `utf-8` รอบแรก ถ้าไม่ผ่านลอง `cp437` ซึ่งเป็นวิธีมาตรฐานของ Werkzeug)

## ข้อกำหนดด้านภาษาไทย (**ความเสี่ยงสูงสุด — อ่านก่อนลงมือ**)

ReportLab และ PyMuPDF **ไม่ทำ complex text shaping** สำหรับภาษาไทย
สระบนล่างและวรรณยุกต์จะไปวางผิดตำแหน่ง ข้อความจะอ่านไม่ออก

**ทางแก้ที่เลือก: วาดข้อความเป็น PNG โปรใสด้วย Pillow แล้วประกอบลงหน้า**
ภาพรวมทั้งเล่มเป็น raster อยู่แล้ว จึงไม่เสียอะไร และได้ผลถูกต้อง 100%

ข้อกำหนด:
- Vendor `NotoSansThai-Regular.ttf` (SIL Open Font License) ไว้ใน `fonts/`
  ห้ามพึ่ง `fc-list` ของระบบ เพราะเซิร์ฟเวอร์จะไม่มีฟอนต์ไทยติดมา
- ต้องการ **Pillow ที่ build มาพร้อม libraqm** เพื่อจัดตำแหน่งสระ/วรรณยุกต์
- **ต้องเช็กก่อนลงมือ** (session นี้ตรวจ environment ไม่ได้ เพราะ bash ถูกจำกัดสิทธิ์):

```python
from PIL import features
assert features.check("raqm"), "ต้องติดตั้ง Pillow ที่มี libraqm"
```

- ถ้า Raqm ไม่มี: ใช้ `uharfbuzz` ต่อ glyph เองแล้ววาดด้วย Pillow
  หรือออกแบบ `text.py` ให้มี fallback ทั้งสองทาง
- วาดข้อความที่ 4× ขนาดจริงแล้วลดขนาดลง เพื่อให้ขอบเรียบแม้ขยายถึง 600 DPI
- ทดสอบด้วยคำที่มีสระบนล่าง/บน + วรรณยุกต์ เช่น "กระต่ายกินผัก" และ "ที่นี่มีปลา"

## ความเสี่ยง

1. **ข้อความไทยผิดรูป** — บังคับ Raqm + ทดสอบตัวอย่างที่ระบุข้างบน ถ้าหลุดให้เปลี่ยนไป `uharfbuzz`
2. **ก้อนทึบขนาดใหญ่หายไป** (ตา ปาก จุดดำของการ์ตูน) — เกณฑ์ตัดจุดรบกวนอิงสัดส่วนพื้นที่
   ต้องทดสอบกับภาพที่มีก้อนทึบจริง และถ้าก้อนทึบใหญ่เกินเกณฑ์ให้คืนพิกเซลเดิมกลับ
3. **XDoG ไวต่อค่าพารามิเตอร์** — ค่าต้อง derive จากภาพจริง และมี slider ให้จูน
4. **หน่วยความจำ** — หน้า A4 300 DPI ประมวลผลทีละหน้า แล้วส่งเข้า PDF แบบ stream
   ห้ามเก็บทุกหน้าไว้ใน RAM
5. **ชื่อไฟล์ไทย/ชื่อซ้ำ** — `imgio.py` ใช้ `np.fromfile` เสมอ, ตัดชื่อไฟล์เป็น slug
6. **ภาพขนาดเล็กมาก** (สติกเกอร์ 500 px) — ขยายไป 300 DPI แล้วเส้นจะเบลอ
   ต้องเตือนใน UI เมื่อความละเอียดต่ำกว่า ~1500 px ด้านยาว
7. **XSS จากชื่อไฟล์** — ชื่อไฟล์ถูกส่งกลับไปแสดงใน DOM ต้อง escape เสมอ
   และตั้ง `Content-Disposition: attachment` พร้อมสร้างชื่อไฟล์ output เอง (อย่าใช้ชื่อจากผู้ใช้ตรงๆ)

## การตรวจสอบผล

**Unit**
- `measure.py`: สังเคราะห์เส้นหนาที่รู้ค่า (เช่น 5 px) → วัดได้ ±1 px
- `convert.py`: ภาพ line art สังเคราะห์ → พื้นหลังขาว (ไม่มี pixel สีเทาค้างเกิน 10%)
  และความหนาเส้นหลังประมวลผลตรงเป้าหมาย
- `text.py`: ข้อความไทยที่มีสระบน/ล่าง + วรรณยุกต์ → ขนาดภาพไม่เป็นศูนย์ และ
  สระไม่ถูกตัดขอบ (ตรวจด้วยการดู bounding box ของหมึก)
- `layout.py`: 10 ภาพโหมด 4 ต่อหน้า → จำนวนหน้า + จำนวนช่องถูกต้องเสมอ
- `pdf.py`: PDF ที่ได้มีจำนวนหน้า = ปก + เพดาน(ภาพ/ช่อง) และขนาดหน้าเป็น A4

**Integration**
- ปล่อยภาพจริง 3 แบบ: line art สะอาด / line art ถ่ายจากกระดาษมีเงา / เส้นหนาผิดปกติ
  → ทุกตัวต้องผ่าน ไม่มี error
- ชื่อไฟล์ภาษาไทย + ชื่อที่มีช่องว่าง → โหลดสำเร็จ
- ภาพ 1 ใบ vs 20 ใบ → เวลาประมวลผลและหน่วยความจำไม่บวมแบบผิดปกติ

**Visual (ต้องทำด้วยตา — ตัดสินใจคุณภาพที่นี่)**
- พิมพ์หน้า 1 จริง แล้วเทียบกับภาพอ้างอิง Canva: เส้นหนาสม่ำเสมอ พื้นขาวสะอาด
  กรอบมุมมนสวย ข้อความไทยอ่านออก
- ยืนยันว่ากรอบไม่ถูกภาพทับ และไม่มีหมึกล้นเข้าขอบกระดาษ

## คำถามที่ยังค้าง (ตอบตอนลงมือได้ ไม่ block)

- โหมดภาพต่อหน้า 1 แบบไหนเป็นค่าเริ่มต้น — แผนตั้งไว้ที่ **1 ภาพเต็มหน้า** ให้ผู้ใช้เปลี่ยนใน UI ได้
- ชื่อกำกับเริ่มต้นดึงจากชื่อไฟล์ — ถ้าผู้ใช้อยากให้ตั้งเองทั้งเล่ม เพิ่มช่องกรอกได้ภายหลัง
- จะต้องมีการเข้ารหัสรูป/ลบไฟล์ชั่วคราวหรือไม่ — เวอร์ชันแรกใช้ in-memory ไม่เขียนลงดิสก์
